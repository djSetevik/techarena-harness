# Этап 5: независимое ревью перед сдачей
Проведи review изменений, не меняя файлы до списка находок. Прочитай AGENTS,
исходные R1/Q1, уточнение U1, OPEN_QUESTIONS, спецификацию и реальные test logs.
Codex для разработки разрешён по сообщению владельца в U1; не отмечай его
использование для кода как нарушение. Проверь отдельно, что оцениваемый runtime
не содержит Codex, его учётных данных или обращений к его API.
Приоритеты: false UNSOLVABLE; expected/cross-task leakage; потерянный usage/
ретраи; синтетические labels без доказательства; нерепрезентативный train/test;
подмена реального oJ пустым import; изменение тестов; secrets в subprocess/образе;
неатомарные ответы; claims о неизвестной финальной команде/модели/SDK.

Для каждой находки укажи severity, файл:строка, сценарий, минимальный тест и
исправление. Отдельно перечисли NOT RUN и спорные требования.
Не выдавай успех mock-тестов за проверку real Qwen/скрытого checker.
После разрешения исправить находки — внеси минимальные изменения и повтори
регрессию. Коммиты и push выполняет владелец после просмотра diff.
