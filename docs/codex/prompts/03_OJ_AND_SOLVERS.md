# Этап 3: подтверждённое API oJ и решатели
Прочитай AGENTS.md, PROGRESS/OPEN_QUESTIONS и спецификацию G/I.
Покажи текущую версию oJ и точные места нужных API в локальном пакете/официальных
исходниках. Не выдумывай классы. Конфликт «любая версия/последняя» не решён;
обновления делай только в окружении проекта и после подтверждения.

Реализуй содержательную интеграцию oJ и единый adapter всех модельных вызовов
через BudgetManager. Usage, retries, max output, timeout должны быть проверяемы.
Fixed-model режим обязателен; никаких вызовов альтернативного провайдера,
проверок vision, embeddings или сжатия вне ledger.

Доработай coding: разрешённые файлы → патч → проверка неизменённых тестов →
краткая ошибка → ограниченный повтор/rollback. Не менять тесты/данные/условия.
Обобщи остальные решатели без жёстких sample-ответов. Воздержание при недостатке
данных важнее уверенной галлюцинации. Обычный subprocess не называть sandbox.

Сначала C01–C06 и regression offline через fake adapter. Живой вызов API не
выполняй без отдельного разрешения, подтверждения допустимой модели и малого
лимита. Ключи только через окружение, не читать .env/системные конфиги.
Если разрешения/ключей нет, готовый интеграционный тест маркируй NOT RUN.
