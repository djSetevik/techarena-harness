# Поэтапная работа

Вместо единственного запроса «сделай всё» используйте последовательность.
Каждый этап: посмотреть git diff → план → код → тесты → docs/PROGRESS.md.
Не делать автоматические коммиты/push и не менять production-сервисы.
Разработка в Codex разрешена по уточнению U1; этот вопрос не является блокером.
Разрешение не переносится на модели внутри оцениваемого runtime.

## Этап 1 — аудит и нулевой LLM-контур
Prompt: prompts/01_AUDIT_AND_OFFLINE.md.
Сверить исходники/источники, отделить labels, воспроизвести baseline. Ввести
TaskSpec, единый writer, трёхзначный detector и unit-тесты search/data.
Реализовать только доказуемые отрицательные случаи; всё остальное UNKNOWN.
Не ломать 6 детерминированных решений на исходных fixtures.

## Этап 2 — бюджеты, прогнозы, scheduler
Prompt: prompts/02_BUDGET_AND_PLANNER.md.
BUDGET в целых десятых, общий ledger, mock usage, ошибки, concurrency, прогноз
до решения, reward/cost приоритет. Пока без real API. Не подменять неизвестный
расход нулём, не учить оценщик по labels/будущим событиям.

## Этап 3 — oJ и общий инструментальный решатель
Prompt: prompts/03_OJ_AND_SOLVERS.md.
Сверить SDK, закрепить версию после согласования, реальный workflow/adapter.
Coding с проверками и rollback, расширение math/search/data, offline моки.
Проанализировать все четыре типа, но не создавать универсальный небезопасный
shell-agent. Live API только отдельным коротким разрешённым тестом.

## Этап 4 — собственные трассы и эксперимент
Prompt: prompts/04_EVALUATION_AND_DOCKER.md.
Синтетические пары solvable/unsolvable/ambiguous; разделение train/test по
родительской задаче/шаблону, а не случайно по почти одинаковым мутациям.
Сравнить baseline, detector, budget и scheduler по отдельности (ablation).
Контейнерный прогон; ключи не копировать в образ; запись ответов сразу.

## Этап 5 — ревью до сдачи
Prompt: prompts/05_REVIEW.md.
Проверить утечки expected, ложные пропуски, учёт ретраев, lifecycle, Docker,
неопределённости R1/Q1. Просмотреть diff, README и тестовые результаты.
Никакая таблица без фактических запусков не превращается в доказанный результат.
