# Правила, источники и нерешённые противоречия

Не сливать противоречивые источники в выдуманное «окончательное правило».
Коды R1/Q1/U1/T1/B1 определены в PROJECT_BRIEF. U1 — переданное владельцем
уточнение о разрешении Codex для разработки; оно закрывает именно этот вопрос.
Остальные проектные решения ниже — инженерные меры, не новые правила жюри.

| Вопрос | Источник и содержание | Рабочее решение / статус |
|---|---|---|
| oJ | R1: на базе oJ; Q1: обязательно | Реальная интеграция и тест пути исполнения, не пустой import |
| Модели | R1: четыре Qwen, включая -noreason, переключение; Q1: две модели разработки, фиксированная при оценке | Отдельный конфиг модели, режим fixed-model; не строить успех на обязательном роутинге |
| Codex для разработки | U1: владелец сообщил о разрешении организаторов использовать Codex сугубо для разработки системы | Вопрос закрыт. Использовать для кода, тестов, отладки и ревью; не требовать повторного подтверждения. Не включать Codex/API Codex в оцениваемый runtime |
| SDK | R1: любая версия, пример 0.1.19; Q1: последняя с официального сайта | Сверить точную допустимую версию, проверить актуальное API в отдельной среде и закрепить версию. Не обновлять production .venv |
| CPU | R1: не более 4, пример docker run: 8 | Временный консервативный профиль ≤4; локально ≤2 |
| Агентность | R1: до 5 одновременных сессий; Q1: сколько угодно агентов | Считать число агентов и конкурентных API-запросов разными понятиями. Default concurrency=1, cap≤5 до уточнения |
| Ответ | R1: OUT и файл решений, затем answer.txt; Q1: рядом с task.json | Для текущего кода answer.txt рядом с task.json. Финальную команду проверить отдельно |
| Coding | Вопрос Q1 о пути и проверке исходников получил только «рядом» | Не считать вторую часть ответа раскрытой. По T1 менять разрешённый модуль, не тесты; DONE после тестов |
| Локальные модели | R1 запрещает локальные нейросети, классика разрешена; Q1 обобщённо разрешает код/модели с лицензией | Пока не включать локальные LLM, embeddings и neural classifiers; обычные правила/регрессия допустимы по R1 |
| BUDGET | Q1: env, ориентир 100000; R1: вход/10 + выход | Чтение env, не hardcode 100000; локальный ledger и резерв перед запросом |
| Остаток | Q1: прокси его не сообщает | Не ждать специального remaining-budget endpoint |
| Отказы прокси | Лимит прекращает ответы; формат ошибки не указан | Сохранять прогресс, не крутить ретраи, классифицировать ошибки по реальному API |
| Финальная команда | Q1: публикация 9 ноября | Не выдавать команду из R1/наших тестов за окончательную |
| Метрики прогноза | Q1: будут опубликованы позже | MAE и штрафы — наши внутренние метрики; не называть их официальной формулой |
| Семантика usage | R1 задаёт стоимость, но не схему JSON прокси | Проверить счётчики входа/выхода/reasoning/cached; не считать неизвестное usage нулём |
| Доказательство нехватки | Q1: нельзя точно решить по имеющимся данным | Для поддержанных форматов хранить свидетельство; остальное UNKNOWN |

Не считать `expected` входом. Не использовать память LLM о мире как замену
отсутствующим локальным фактам. Интернет/другие задачи не являются автоматическим
разрешением дополнить конкретную базу знаний.

## Закрытый вопрос: Codex как инструмент разработки
По U1 разрешение получено владельцем проекта. Не переносить его в список
открытых вопросов и не останавливать реализацию из-за старой оговорки.
Это уточнение не распространяется автоматически на другие сторонние модели
и не меняет ограничения для оцениваемого харнесса.

## Вопросы организаторам перед финалом
1. Какая модель будет фиксированной, как передают её имя и доступен ли -noreason?
2. Какая точная версия/релиз openJiuwen считается требуемой последней?
3. Окончательная docker-команда, CPU и лимит параллельных сессий?
4. Как проверяют изменённые coding-исходники, какие артефакты прогнозов требуются?
5. Какая точная семантика usage и ответ на исчерпание бюджета?

Наличие этих вопросов не мешает разрабатывать проект в Codex и выполнять
offline-тесты. Вызовы конкурсного прокси и финальные ограничения учитываются отдельно.
