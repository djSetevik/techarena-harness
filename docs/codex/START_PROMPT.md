Я продолжаю существующий проект TechArena 2026 — конкурсный Python-харнесс
на openJiuwen. В репозитории уже есть run_agent.py, Dockerfile и src/solvers.py.
Не начинай новый чат-бот и не переписывай работающие службы JiuwenSwarm/heartbeat.

По уточнению U1 владелец получил разрешение организаторов использовать Codex
сугубо для разработки системы. Не ставь это под повторное согласование и не
блокируй работу из-за прежней оговорки. В финальном контейнере Codex и его API
не используются: остаются openJiuwen и разрешённые модели через прокси.
Источник: docs/codex/materials/clarifications/codex-development-authorization.ru.md.

Сначала прочитай AGENTS.md и docs/codex/PROJECT_BRIEF.md,
docs/codex/RULES_AND_OPEN_QUESTIONS.md, затем исходные материалы в
materials/original и задание docs/codex/prompts/01_AUDIT_AND_OFFLINE.md.

Суть задачи: есть 100 задач четырёх типов — math, search, data_analysis, coding;
reward виден заранее, expected в финале отсутствует. Общий бюджет передаётся
через BUDGET, ориентир 100000. Прокси не сообщает остаток. Невыполнимая задача —
та, которую нельзя точно решить по имеющимся данным. За её пропуск баллов нет,
но важно не расходовать на неё LLM-токены. Ответы сохранять атомарно в answer.txt
рядом с task.json; для пропущенных/нерешённых задач не создавать файл.

Главный приоритет: консервативный детектор SOLVABLE/UNSOLVABLE/UNKNOWN.
Не найденное регулярным выражением поле не доказывает нехватку данных.
UNSOLVABLE требует свидетельства; UNKNOWN остаётся кандидатом планировщика.
Не использовать expected, task_id или готовые ответы как признаки/решения.
Не смешивать базы знаний разных задач. Сначала дешёвые вычисления без LLM.

Сейчас выполни только этап 1: аудит, отделение тестовых эталонов, воспроизведение
baseline, корректный loader/writer и offline-detector с тестами для search/CSV.
Не делай живых API-вызовов, не обновляй системные зависимости, не меняй SSH,
systemd, heartbeat, ключи или установку JiuwenSwarm. Не выполняй push.

Уточнения правил содержат противоречия по моделям, версии oJ и финальной команде.
Не придумывай окончательные требования; вынеси оставшиеся вопросы в
docs/OPEN_QUESTIONS.md. Старый вопрос о допуске Codex к разработке отметь
решённым по U1, если он уже был записан.
Сначала покажи короткий план, затем внеси изменения и реально выполни доступные
offline-тесты. Заверши списком файлов, результатами PASS/FAIL/NOT RUN и записью
в docs/PROGRESS.md. Не объявляй моки проверкой настоящего API или скрытого набора.
