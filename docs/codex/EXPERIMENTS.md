# План данных и проверки гипотез

Источник исходных 8 задач — T1. По R1 они все выполнимы. Прогноз на финальные
100 задач по этим восьми не оценён. Готовые трассы организаторы не предоставляют (Q1).

## Синтетика
Создавать семейства: original → paraphrase/rename → solvable missing-irrelevant
→ truly missing-required → redundant-evidence → contradictory/ambiguous.
Сохранять seed, parent, изменение, истинную метку и её обоснование отдельно
от runtime-каталога. Задания с разными task_id из одного шаблона не независимы.

Для UNSOLVABLE сохранять два допустимых дополнения данных с разными ответами
или явно оговорённое закрытое множество разрешённых фактов. Если удалённый
факт выводится из другого места, задача всё ещё решаема. Если генератор не может
подтвердить метку, пометить её UNKNOWN/unreviewed и не считать эталоном.

Для coding не генерировать «невыполнимость» простым удалением тестов: спецификация
может быть достаточна. Не обучать модель признакам произвольных шаблонов порчи.

## Сравнения
Одинаковые задачи/seed/лимиты: baseline → +feasibility → +budget → +scheduler.
Измерять false-skip weighted reward и реальные сэкономленные расходы, а не
только accuracy бинарного classifier. UNKNOWN отдельно. Выбрать порог отказа
на train/validation; не подгонять по test.

Исходный прогноз затрат — до исполнения; итог — отдельно. Неуспешные/прерванные
попытки имеют фактическую нижнюю границу расхода, но не обязательно известную
полную стоимость решения. Пропущенная задача не даёт метку стоимости решения.
Реальные API-трассы собирать только на разрешённых моделях с отдельным лимитом.

## Минимальный журнал
run_id, source_revision, task_hash, family_split, task_type, reward,
predicted_cost_units, estimate_status, feasibility_status/reason/evidence,
llm_calls, actual_cost_units, unresolved_cost_units, verification_status,
answer_saved, wall_time_ms. Данные не содержат API-ключей, ssh-ключей или
учётных данных Codex/GitHub. Сырые prompts — только по явному выбору владельца.

## Цель первого цикла
Не обещать «распознаём все нерешаемые». Получить 0 ложных UNSOLVABLE на проверенных
положительных fixtures; для отрицательных с доказательством — 0 LLM-вызовов;
сохранить воспроизводимый baseline и выдать отчёт о том, какие случаи UNKNOWN.
