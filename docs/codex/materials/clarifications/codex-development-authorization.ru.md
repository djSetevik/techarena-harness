# U1 — Codex разрешён для разработки системы

Источник: уточнение владельца проекта в этой переписке. Владелец сообщил,
что после телефонного согласования с организаторами получил разрешение
использовать Codex сугубо для разработки системы. Зафиксировано 8 ноября 2026.
Это дополнительное пользовательское уточнение, не новая опубликованная редакция
регламента; исходные R1/Q1 сохранены без изменений.

## Принятое правило проекта
Codex CLI разрешён как помощник разработки конкурсного харнесса:
проектирование, написание и правка кода, подготовка тестов, отладка и ревью.
Вопрос о допуске Codex к этой работе закрыт. Не требовать повторного разрешения
на его использование для разработки и не останавливать из-за этого реализацию.

## Граница разрешения
Это не разрешение использовать Codex как модель-решатель в оцениваемом прогоне.
Финальный харнесс сохраняет обязательную интеграцию openJiuwen и использует
только разрешённые организаторами модели через их LLM-прокси. Codex CLI,
его учётные данные и вызовы его API не включаются в конкурсный runtime.
Уточнение не расширяет разрешение на другие сторонние LLM и не отменяет
оставшиеся вопросы о финальной модели, версии oJ и команде контейнера.

Вызовы конкурсного прокси при тестировании харнесса по-прежнему ограничены
выданным бюджетом. Разрешение Codex не даёт доступа к приватным ключам,
серверным службам или другим секретам и не разрешает незапрошенный push.

## Приоритет при чтении материалов
При обсуждении допустимости Codex для разработки учитывать U1 вместе с R1/Q1.
Не переносить старую оговорку об отсутствии разрешения в новые задания.
Если в docs/OPEN_QUESTIONS.md уже есть такой пункт, отметить его решённым
со ссылкой на U1; остальные вопросы не закрывать автоматически.
