# Приёмочные тесты (наши критерии, не официальные скрытые тесты)

Не писать «всё проверено», если часть проверок пропущена. Для каждого ID указывать
PASS/FAIL/NOT RUN, команду и результат. Моки не заменяют live-интеграцию.

## P0: ввод, эталоны и существующий baseline
- A01. Дано 8 исходных задач, подготовщик создаёт ровно 8 runtime task.json,
  без expected и answer.txt, с исходными workspace-файлами.
- A02. До доработок baseline в offline-режиме воспроизводится на свежей копии;
  эталоны сверяет внешний grader, не runtime. Исторический ориентир: 6/8, 16 баллов.
- A03. Добавление фальшивого expected в тестовый task.json не меняет действия/ответ;
  runtime TaskSpec и промпт его не содержат. Fixture labels не доступны solver.
- A04. Переименование каталогов/task_id/сущностей и изменение reward не подменяют
  смысл решения. Task_id не является таблицей ответов.
- A05. Runtime сохраняет answer только рядом с task.json. Пустая/пропущенная задача
  не создаёт ни пустой answer, ни workspace/answer.txt.
- A06. Исходный архив/тесты не мутируют; повторный тест использует свежую копию.
- A07. Все результаты и прогнозы имеют task scope; одинаковая сущность в двух kb
  с разными фактами даёт независимые ответы, нет cross-task leakage.

## P1: отрицательные и контрпримеры для Feasibility Detector
Синтетические изменения и их метки создаём сами. Они не являются скрытым набором.
Каждая метка UNSOLVABLE сопровождается минимальным свидетельством/двумя мирами,
либо проверяемым доказательством отсутствия обязательного элемента закрытой схемы.
Если такого обоснования нет — UNKNOWN, не «синтетическая истина».

| ID | Тест | Ожидаемое поведение |
|---|---|---|
| F01 | В распознанной закрытой KB нет запрошенного факта, альтернативных выводов нет | UNSOLVABLE + evidence, 0 LLM, answer отсутствует |
| F02 | Нужный факт есть в другом допустимом файле той же задачи | Не UNSOLVABLE; решение/поиск по полному scope |
| F03 | Нет поля Born, но факт дан свободным текстом | UNKNOWN либо корректно извлечённый факт; не ложное доказательство отсутствия |
| F04 | Не найдено промежуточное ребро employer→company в полной закрытой схеме | UNSOLVABLE только после проверки альтернатив/aliases |
| F05 | Есть два противоречивых факта без правила приоритета | Не выбирать первый; evidence неоднозначности либо UNKNOWN |
| F06 | Противоречие снимается явно заданной датой/приоритетом | Не отбрасывать как невыполнимую |
| F07 | Ограничен размер сканирования, часть KB не прочитана | UNKNOWN, scope_complete=false |
| F08 | CSV полный, совпадений по фильтру нет, спрашивают сумму | Корректный 0, не пропуск |
| F09 | У релевантной строки не указан units и нет формулы восстановления | Evidence разных возможных итогов; не считать 0 автоматически |
| F10 | Колонка units отсутствует, но задана точная формула из других колонок | Решать/UNKNOWN, но не UNSOLVABLE из одного отсутствия колонки |
| F11 | Пропуск только в нерелевантной строке/ненужной колонке | Не ложный UNSOLVABLE |
| F12 | Неизвестный CSV dialect/файл недоступен из-за permissions | UNKNOWN/IO_ERROR, не логическая невыполнимость |
| F13 | В math неизвестная независимая величина меняет ответ | Два допустимых значения → UNSOLVABLE |
| F14 | Неизвестный x, но ответ x*0 | 0, не ложный пропуск |
| F15 | Новая операция в тексте math не распознана | UNKNOWN, не частичное вычисление |
| F16 | Нет тестов, но полная спецификация coding есть | Не UNSOLVABLE только из-за отсутствия тестов |
| F17 | Код не проходит тесты | Кандидат на ремонт, а не невыполнимая задача |
| F18 | Отсутствует исходник, но тесты однозначно задают нужное поведение | Не автоматический UNSOLVABLE |
| F19 | Есть неизвестная цель/неполная спецификация coding | UNKNOWN, если нет формального свидетельства неоднозначности |
| F20 | Нехватка API-ключа/бюджета | skip_reason=credentials/budget, статус задачи не подменяется |

Для начального набора цель: 0 ложных UNSOLVABLE на 8 исходных и положительных
контрпримерах. Это локальный quality gate, не гарантия на любых формулировках.
Считать не только число ошибок, но и потерянный reward решаемых задач.

## P2: токены и планировщик
- B01. input=2000, output=500 including reasoning → стоимость 700, а не 2500.
- B02. output уже включает reasoning → повторно не прибавлять; другой формат,
  где reasoning отдельно, корректно нормализуется по подтверждённой схеме.
- B03. cached input учитывается полностью. Дроби input/10 не теряются на округлении.
- B04. BUDGET=0 → 0 LLM-вызовов, детерминированные решения всё равно сохраняются.
- B05. Неверный/отрицательный BUDGET → понятная ошибка до первого платного вызова.
- B06. Два конкурирующих запроса не резервируют один остаток дважды.
- B07. Timeout после отправки запроса не превращается в стоимость 0.
- B08. JSON/compile/test-ошибка после ответа модели не теряет usage.
- B09. Скрытые SDK retries отключены или учитываются каждый отдельно.
- B10. Исчерпание прокси → остановка новых платных вызовов без retry loop.
- B11. Отсутствующее usage → явная неопределённость/консервативный резерв, не ноль.
- B12. predictions записаны до первого solve/model шага и неизменны после него.
- B13. UNKNOWN с высокой выгодой может быть выбран; UNSOLVABLE с доказательством
  не получает LLM-вызов независимо от reward.
- B14. Три mock-задачи с известными стоимостью/вероятностью/наградой демонстрируют
  выгодный порядок, а расход не превышает доступные резервы.
- B15. Skipped-задачи не становятся обучающими примерами «стоимость решения = 0».

## P3: coding и oJ
- C01. SDK реально участвует в execution path; это подтверждается тестом/trace,
  а не только наличием зависимости. Версия/импорты сверены.
- C02. Mock LLM возвращает неудачный патч, затем исправление: оба usage учтены,
  тесты неизменны, ответ пишется только после проверки.
- C03. Compilation error/timeout → свои правки откатываются, нет ложного DONE.
- C04. Путь ../outside.py/симлинк вне разрешённой области отвергается.
- C05. Изменение тестов/данных для получения pass отвергается.
- C06. Subprocess env не содержит LLM_API_KEY, SSH_AUTH_SOCK или credentials;
  лимиты времени и stdout проверяются. Это не заявление о полноценной изоляции UID.
- C07. Реальный smoke через разрешённую модель: только с отдельным согласием,
  маленьким BUDGET/лимитом вывода; записать usage, не секреты. Иначе NOT RUN.

## P4: Docker и сдача
- D01. Сборка с закреплёнными версиями <1000s; размер образа <4 GB.
- D02. Запуск read-only + HOME=/tmp + tmpfs; task mount writable; answer рядом.
- D03. Offline-прогон с --network none не делает сетевых попыток/скачиваний.
- D04. В образе нет raw task archive, expected, .env, .git, SSH/RegID/CLI credentials.
- D05. Обработка SIGTERM/прерывания не теряет ранее сохранённые ответы.
- D06. README содержит реальные команды, стратегию detector/estimator,
  ограничения, нерешённые вопросы и результаты, без вымышленных метрик.
- D07. Final команда/модели/SDK из последней публикации проверены перед сдачей;
  пока её нет — NOT RUN / pending, а не предположение.
